ATransport & connection

WebRTC — why, not WebSocket

Real-time media transport, built for voice.

  • TCP/WS → head-of-line blocking: one lost packet stalls the rest.
  • WebRTC/UDP → skip a lost packet > wait for it.
  • Opus codec · timestamps · jitter buffer · adaptive bitrate.

firewall ICE probes: STUN → direct → TURN on 443 (looks like HTTPS). ~60–70% relay in corp nets — LiveKit runs it.

Room · participant · track

The data model, and the SFU that routes it.

  • Room = the session container.
  • Participant = caller, agent, human, SIP caller (kind: standard/agent/sip).
  • Track = a media stream you publish; others subscribe.
  • SFU = selective forwarding (routes, doesn't mix); self-heals via session migration.
sayThe agent is a participant, not a backend the room calls.

Tokens & grants

Signed JWT = your key to one room.

  • HMAC-SHA256 w/ API secret · minted server-side.
  • Carries: identity (UUID) · room+roomJoin · canPublish/Subscribe · exp.
  • Agent dispatch: RoomConfiguration(agents=[RoomAgentDispatch(...)]).

don't forget secret can't be in a browser · no PII in identity · sandbox token server = dev only.

BThe voice pipeline

VAD → STT → LLM → TTS

Four components; each streams & overlaps.

  • VAD — speech present now? drives barge-in (Silero).
  • STT — audio→text; interim / final / preflight.
  • LLM — what to say + which tool; streams tokens.
  • TTS — text→voice; streams from first words.
sayCascaded — swap any stage, failover per stage, clean transcript.

Turn detection & barge-in

Did they finish the thought? (not just a pause)

  • VAD = speech present · turn model = thought complete.
  • LiveKit's own open-weights model (fine-tuned Qwen2.5-0.5B). ~20 ms.
  • False-cutoff @300 ms: 9.9% vs 12.9% Flux vs 27.7% VAD-only.
  • Barge-in: keep listening while speaking → cancel TTS, flush, back to STT.

don't forget the turn detector is the ONE model LiveKit owns — everything else is third-party they serve.

Latency & metrics

VAD15–30 ms
STT200–600 ms
LLM100 ms–1 s
TTS100–300 ms
  • Targets: <500 ms ideal · TTFA <1 s solid.
  • TTFA = felt · TTFT = diagnostic · EOU = turn delay.
  • Also: interrupt rate, tokens/cost, fallbacks.

Preemptive generation

preemptive_generation=True

  • LLM starts thinking on a stable preflight transcript, before end-of-turn.
  • Waits for clear EOU to speak — but thinking already started. Saves 100s of ms.

skip for mid-sentence direction changes · multi-part instructions · medical/legal/financial.

Resilience — FallbackAdapter

Per-component failover, built in.

  • stt.FallbackAdapter([primary, secondary]) — same for LLM/TTS.
  • Retries in priority order, never drops the call. User never knows.
  • e.g. AssemblyAI→Deepgram · OpenAI→Gemini · Cartesia→InWorld.
sayThe structural reason to stay cascaded — I fail over per component.

CThe Agents framework

Worker → dispatch → job

How the agent gets into the room.

  • Agent code registers as a worker, waits for jobs.
  • User joins room → LiveKit dispatches a job to an available worker.
  • Worker starts an AgentSession subprocess that joins the room.
  • Run modes: console (local, no room) · dev · start (prod).

don't forget stateful load balancing pins a session to one worker for its life.

Tools — 3 kinds

function@function_tool, in-process — hot path
MCPseparate service — external, shared, own deploy
providerbuilt into LLM — web search, code exec
  • Docstring is critical — LLM reads it to pick the tool.
  • Keep <2 s or session.say("let me look…") · ToolError on fail.
  • Disable interruptions for irreversible actions · max_tool_steps (default 3).
  • MCP: fetched at connect, registered alongside local tools.

Tasks · workflows · handoff

  • Task = scoped unit returning a result (consent → bool); on_enter.
  • Handoff = tool returns (NewAgent, "msg"); pass chat_ctx to keep history.
  • Task group = steps in sequence (email→address); can go back to correct.
  • Consent = recording permission (often legally required); record=False if declined.
  • Human = SIP: disallow interruptions → publish SIP participant.

flow consent → triage → specialist → manager → human (last resort). Context preserved each hop.

DModels & operations

LiveKit Inference & models

Managed STT/LLM/TTS — zero-config, one gateway.

  • Providers: OpenAI, Google, AssemblyAI, Deepgram, Cartesia, ElevenLabs…
  • Zero data retention by default — nothing logged/trained on. (Medical win.)
  • Cascaded vs realtime (speech-to-speech) vs half-cascade (realtime ear + TTS mouth).

don't forget a Google model here is served by LiveKit, not your Vertex.

Observability

Built into LiveKit Cloud.

  • Transcript + traces + logs, all on one synced timeline w/ audio playback.
  • Traces = per-turn spans (STT/LLM/TTS/tools) → find the bottleneck.
  • Enable at project level · OTel-compatible · US, 30-day retention.
  • record=False per session for sensitive data.

Deploy · Agent Builder

  • lk agent create → registers, writes livekit.toml, auto Dockerfile, builds, deploys.
  • LiveKit Cloud hosting = autoscale + load-balance + global net + observability.
  • Regions: US East, EU Central.
  • Agent Builder = no-code UI → generates the same SDK code ("a pathway to code").

your build you chose GKE over LiveKit hosting for graceful drain + data-boundary — name that tradeoff.

SIP / telephony & extras

  • SIP = signaling (who/where) · RTP = the audio. Trunk + dispatch rule → SIP participant joins the room.
  • Transfer: cold (REFER) vs warm (same-room). publish SIP participant to bridge a human.
  • Background Voice Cancellation — LiveKit noise/background-speaker suppression tuned for agents.
